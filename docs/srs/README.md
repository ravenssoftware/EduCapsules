# SRS reference

`EduCapsules_Master_SRS_v1.0.docx` is the canonical source of truth for this project — **the official, consolidated Master SRS baseline**, per the Project Owner's explicit redesignation (13 September 2026). Its internal "Document Version" field also reads 1.0.

**Naming note, to avoid confusion:** while this specification was being audited and extended, its internal iteration numbers ran 0.1 through 1.4. None of those iterations was ever committed to this repository under a "v1.0" filename — the first file this repository ever committed was the v1.1 audit. The Project Owner has now designated the fully consolidated result of that entire 0.1–1.4 lineage as the repository's **Version 1.0** — a fresh, forward-looking version number the Project Owner adopts going forward, not a reversion to an earlier draft. Below, "v1.0" describing the *original supplied specification* refers to a different, historical, pre-repository thing; the document's own front matter (§1.1) and a "BASELINE REDESIGNATION" note before Appendix E (§52.5) make this distinction explicit inside the file itself too.

## What this baseline consolidates

The current file is the byte-level output of the following development lineage. Every change is itemised in the document's own Appendix E (§52.5); v1.1's amendment summary is also in §1.7.

- **Original draft** (pre-repository, historically called v1.0): the specification package EduCapsules was originally built from.
- **Audit pass** (tracked internally as v1.1): no CONFIRMED decision was reversed; it resolved internal defects the original draft had (contradictions between two CONFIRMED sections, a duplicate requirement ID, four requirements that were cited but never defined, and several mis-wired cross-references).
- **D-08 resolution** (tracked internally as v1.2): grade scales are configurable per Organization, never a single global scale, with the scale and criteria in force at grade creation/release permanently preserved. Adds GRD-013...020, the GradingScale/GradingScaleVersion entities, the GRADING_SCALE_MANAGE permission, and the `/grading-scales` API resource group.
- **D-16 provenance classification** (tracked internally as v1.3): every requirement in §9 (Classroom/Group) and §21 (Assistant) whose source specifications were never supplied is individually classified as CONFIRMED elsewhere (independently corroborated by a golden rule, another section, the data model, or a worked use case) or PROVISIONAL (reconstructed by inference only — Tables 9.1a and 21.1a). No requirement text was changed or invented — a labeling pass only, verified byte-for-byte against the prior iteration.
- **Flutter client-strategy decision** (tracked internally as v1.4): Flutter replaces the responsive-web-client decision — Flutter Desktop (Windows/macOS/Linux) for V1, the same codebase extending to Android/iOS as a future release, release timing a Project Owner decision rather than an unmet-requirement trigger. Updated: §5.2 (client applications), Table 41.1 and the PLATFORM DECISION box, the "Static client delivery" row of Table 41.3, FE-001/003/004/010 (§41.2), AUTH-125 (§35.2), UI-010/015/016/017/018 (§42.6), PERF-004/005 (§43.1), NFR-021/022/023 (§43.5), Table 49.1/49.2 (§49), and CON-05 with new risk R-14 (§50). Full rationale, alternatives considered, and consequences in [`docs/decisions/06-flutter-client-decision.md`](../decisions/06-flutter-client-decision.md).
- **Baseline redesignation** (this file — Version 1.0): consolidates everything above into one document and relabels it the official Version 1.0 the Project Owner uses going forward, per explicit instruction. **No requirement, decision, or content changed in this step** — only the document's own version label (cover page and §1.1) and a new explanatory note before Appendix E changed. Verified by a byte-level diff against the pre-redesignation content.

`EduCapsules_Master_SRS_v1.0.md` is a plain-text/Markdown mirror of the same content (pandoc-extracted), kept for fast grep/search during implementation — it is not a separate source of truth, just a convenience copy of the .docx.

Requirement IDs referenced throughout the codebase (e.g. in code comments, test names, or the traceability matrix) should point at IDs in this document. **Before implementing anything in §9 or §21's territory (Phases 5–6, 16), check Tables 9.1a / 21.1a first** — PROVISIONAL requirements (CLS-002, CLS-003, GRP-002, AST-009, and two rows of Table 21.2) are safe to build against provisionally but their final behavior awaits Project Owner confirmation. **Before implementing any client-facing screen or component (Phases 14–17, 22, 26), read `docs/decisions/06-flutter-client-decision.md` and §41.1/§5.2 first** — the client is Flutter, not React/Vite; any earlier reference to a web/browser client anywhere in this repository is superseded/historical unless it is explicitly about that decision record.
